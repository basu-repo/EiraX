# Västervik physical-robot workspace

This directory follows the Linköping/Halmstad colcon workspace layout used on
the robots. The authoritative code is under `src/`. The `build/`, `install/`
and `log/` directories are generated on each target computer and are not
portable between computers.

```text
implementation/
├── src/
│   ├── lrs_halmstad/
│   └── lrs_halmstad_gui_plugins/
├── build/                 # generated by colcon
├── install/               # generated by colcon
└── log/                   # generated by colcon
```

Build from the workspace root:

```bash
source /opt/ros/jazzy/setup.bash
rosdep install --from-paths src --ignore-src -r -y
colcon build --symlink-install
source install/setup.bash
```

`build/` contains compiler/Python packaging intermediates. `install/` is the runnable overlay produced from the source. `log/` records colcon invocations and failures. None is authoritative, and all three can be regenerated from `src/`.

For a faster main-package rebuild:

```bash
colcon build --symlink-install --packages-select lrs_halmstad
source install/setup.bash
```

After changing Python source in a symlink build, verify that the active overlay is this workspace:

```bash
ros2 pkg prefix lrs_halmstad
```

It should resolve below this implementation's `install/` directory. If ROS loads another workspace, open a clean terminal and source `/opt/ros/jazzy/setup.bash` followed by this workspace's `install/setup.bash`.

The YOLO file under `install/lrs_halmstad/share/...` is a packaged output. Its authoritative copy is under `src/lrs_halmstad/models/...`.

The original Halmstad hardware descriptions and interfaces remain intact.
Västervik behavior is added inside `lrs_halmstad.coordination` and
`lrs_halmstad.vastervik_husky`. Gazebo simulation nodes must not be started on
the physical robots.
